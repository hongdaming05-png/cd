# MVP 假設與後續方向

## 第一版要驗證什麼

長輩在沒有家人代操作的情況下，能否完成一項簡單設定；卡住時，提示能否讓他回到操作流程。
不以聊天回覆的豐富程度衡量成功，先觀察實際操作。

試用方式建議：邀請 3–5 位長輩，各做「iPhone 字體放大」或「LINE 聊天字體放大」。
先說明是試用，記下手機與 App 版本，避免一開始就示範完整答案。

| 觀察項目 | 記錄方式 |
| --- | --- |
| 能否開始 | 是否知道從搜尋或卡片進入 |
| 能否完成 | 是否親自做到目標設定、是否需要家人代操作 |
| 卡在哪一步 | 按鈕名稱、圖示定位、滑動、切換 App，分別記錄 |
| 提示是否有幫助 | 按求助後能否往下完成 |
| 同機切換成本 | 是否能從設定回到教學、是否忘記上一句 |
| 朗讀實用性 | 語速、用詞、聲音是否聽懂，背景是否中斷 |
| 任務時間 | 實際完成時間，不能只看網頁的完成按鈕 |

不要只依據「做到了」計算任務成功；請觀察手機最後的實際結果。
這些資料先人工記錄即可，第一版未做分析儀表板或追蹤系統。

## 已實作

- 繁體中文、大字與再放大按鈕、桌面與手機排版。
- 四份有官方來源的教學、大按鈕、一次一個動作、確認點與示意圖。
- 目前步驟朗讀與停止、卡住提示、教學 FAQ、完成後再練習。
- 進度持久化、重複點擊保護；本機與雲端模型 adapter，預設關閉。

## 下一輪優先順序

1. **實機與長輩試用**：核對 iPhone／LINE 實際版本、收集卡住位置和問法。
2. **把最常卡住的教學做好**：加入有授權的截圖標註或短片；增加讀音、語速與用詞的實測。
3. **改善查找**：建立查詢評估集，再決定是否增加 embeddings、reranker 或意圖澄清。
4. **啟用模型並評估**：比較本機和雲端回覆，檢查是否產生額外步驟、是否真的幫助完成。
5. **更多裝置／版本**：先有版本內容，再加入裝置與版本的選擇方式。

若目標是自動辨識手機畫面，網頁本身無法讀取別的 App。需要另外設計使用者提供截圖／錄影、
原生 App 或其他明確分享畫面的機制；那會是獨立一輪的產品與技術驗證。

## 後期：子女教學與共享內容

這個方向先保留在設計文件，第一版沒有上傳／公開分享入口。
成熟後可以採取：「上傳操作錄影 → 擷取候選步驟 → 標示裝置與版本 → 人工校對 → 審核發布」。
使用者的聊天室、通知、聯絡人或其他私人資訊需要在分享前移除；
也需要作者同意、授權、內容審核、版本修訂與失效下架的流程。

結構化的 Guide 模型可當作未來影片處理的產出格式，投稿內容通過審核後，
才能加入已發布知識庫。先驗證「這種教法是否有用」，再投資大量內容生產功能。
